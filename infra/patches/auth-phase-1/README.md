## How to apply (Admiral, after Phase 0 secrets are generated)

These patches are **NOT meant to be applied sequentially** — each one
also adds the imports (`Depends`, `verify_admin_token`) at line 17, so
applying patch 01 then patch 02 would conflict on the imports hunk.

**Recommended workflow for Phase 1a (single-route ship):**

1. Generate the 3 secrets per `docs/AUTH_SETUP.md`
2. Verify `pytest tests/test_auth.py -v` is 11/11 green from the trader venv
3. `git apply infra/patches/auth-phase-1/01-kill-switch.patch`
4. Restart trader
5. Run TIER A smoke test (next section)
6. Soak for one trading day; observe the route still works under TOTP
   bearer + service-token bearer + recovery key
7. If green, repeat for routes 02-07 — but only the route-signature
   hunks; the imports are already in place from step 3 so subsequent
   patches need their first hunk dropped.

**Recommended workflow for Phase 1a (batch all 7 in one PR):**

```bash
# Apply only the imports + first route from patch 01
git apply infra/patches/auth-phase-1/01-kill-switch.patch
# For 02-07, use only the second hunk of each (the route signature change)
# Easiest: apply each, then use --include or hand-edit to keep only the route hunks
for p in 02 03 04 05 06 07; do
  # extract second hunk only (lines from the second @@ to EOF)
  awk '/^@@ -[0-9]+,/{ count++ } count >= 2' \
    infra/patches/auth-phase-1/${p}-*.patch \
    | git apply --include="dashboard/app.py" -
done
```

(Alternatively, generate a single combined `tier-a-combined.patch`
manually after the import hunk lands — left as Admiral exercise to
keep these draft files small and reviewable.)

## Per-route smoke test

After each patch applies and trader restarts, run the equivalent of
`tests/test_auth.py` against the live route:

```bash
# Pick the route under test — example: kill-switch
ROUTE="/api/kill-switch"
HOST="http://127.0.0.1:8080"

# 1. Missing bearer → 401
curl -X POST -s -o /dev/null -w "%{http_code}\n" "${HOST}${ROUTE}"
# expect 401

# 2. Bad bearer → 401
curl -X POST -s -o /dev/null -w "%{http_code}\n" \
  -H "Authorization: Bearer bogus" "${HOST}${ROUTE}"
# expect 401

# 3. Valid service token → 200 (or whatever the route returns)
curl -X POST -s -o /dev/null -w "%{http_code}\n" \
  -H "Authorization: Bearer ${OLLIETRADES_SERVICE_TOKEN}" "${HOST}${ROUTE}"
# expect 200 — but note this WILL execute the kill switch! For dry
# verification, swap to a non-mutating tier-A route or accept the side effect

# 4. TOTP code from authenticator app → 200
TOTP="123456"  # current code from your app
curl -X POST -s -o /dev/null -w "%{http_code}\n" \
  -H "Authorization: Bearer ${TOTP}" "${HOST}${ROUTE}"

# 5. (Skip recovery-key smoke test — the sentinel will get burned)
```
