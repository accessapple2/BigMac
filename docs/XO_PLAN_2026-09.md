Started 2026-09-09, after the after-hours 8B-vs-30B bakeoff
(`data/reports/relay/relay_2026-09-09_mccoy-8b-vs-30b-bakeoff.md`). That
session surfaced two structural gaps that motivate this plan: (1) no forward

never been measured directly; (2) `decision_audit` didn't persist prompts
(fixed same night, commit `e81b3af`) — a symptom of decision *structure*
(thesis, invalidation, sizing) not being captured anywhere queryable either.

This plan is phased, cumulative, and gated — each phase only starts once
the prior one has run long enough to trust its numbers. Nothing here
authorizes trading actual capital; every phase operates on the existing
Alpaca paper book per `RULE #1` in `CLAUDE.md`.

## Phase 0 — Baseline (starts 2026-09-09, read-only)

**What:** a daily script, no writes to `trader.db`, that:
1. Pulls McCoy's (`ollama-plutus`) BUY signals for the trading day.
2. Dedupes by symbol (highest-confidence instance per symbol), ranks by
   confidence, takes the top 20.
3. Computes each one's forward return from signal timestamp to that day's
   13:00 MST close (Alpaca IEX 1-min bars — same methodology as the
   2026-09-09 bakeoff).
4. Compares the equal-weighted top-20 average return to SPY's open-to-close
   return the same day.
5. Writes a dated report file under `data/reports/mccoy_baseline/` (JSON +
   printed summary) — no DB writes, no trades, no config changes.

**Why:** every later phase (structure changes, McCoy Rank, hedging) needs a
"compared to what" — this is that number, running before anything else
changes so later deltas have a pre-change baseline to compare against.

**Cadence:** daily after close (cron, ~13:10 MST — after the 13:00 close so
the day's bars are final). First run: today, 2026-09-09, manually.

**Acceptance:** none — this phase doesn't gate on a number, it *produces*
the numbers everything else gates on. Runs indefinitely alongside every
later phase.

## Phase 1 — Structure (one change per day, each with an acceptance check)

Each sub-phase ships alone, runs at least one full trading day, and is
checked against its acceptance criterion before the next one starts. No
sub-phase touches sizing or execution live until its own day has run clean.

- **1.1 — Thesis + required invalidation.** Shipped 2026-09-09 evening,
  commit pending restart. McCoy's prompt already asked for a thesis in
  prose ("THESIS REQUIREMENT" in `providers/base.py`); this adds a
  structured, required `Invalidation:` output line — a specific price
  level, not a description — checked by
  `engine/providers/base.py::check_invalidation_missing()`: must name a
  parseable price, on the correct side of the reference price (below for
  BUY/BUY_CALL, above for SHORT/BUY_PUT), 0.5%-15% away from it. Purely
  observational (logs `INVALIDATION-IMPLAUSIBLE`, never blocks or alters
  the decision), same posture as the existing
  `check_reasoning_direction_conflict`. The format change lives in the
  shared prompt template (`build_prompt()` / `build_execute_prompt()`) so
  any future fleet seat inherits it, but **acceptance is judged on McCoy
  only** — he's the only seat that emits Arena signals. Stored on
  `signals.invalidation` + `signals.reference_price` (the price the model
  was shown, so plausibility is recomputable offline without an Alpaca
  round-trip). Acceptance script: `scripts/mccoy_invalidation_acceptance.py`
  — bar is **≥90% of directional signals plausible** (not just non-empty),
  first read 2026-09-10 after that session closes.
  - **1.1b (later, after 1.1 clears its bar — not built now):** fold the
    signal's invalidation into the hard-stop sweep in `sell()`/
    `sell_partial()` (the same sweep Desk-opened positions already run
    through) — a position opened from a signal uses that signal's
    invalidation as its stop, falling back to the existing generic
    hard-stop when none was captured.
- **1.2 — Screen-then-score, continuous scan stopped.** A deterministic
  screen runs first (liquidity/volume/price filters, no LLM) producing a
  ranked universe; McCoy scores only the top ~100 of that list, twice a day
  (pre-open, midday) instead of continuously every 120-300s
  (`main.py::_get_scan_interval`). Cuts LLM call volume by roughly two
  orders of magnitude and removes the "same symbol re-scanned every few
  minutes" noise seen in the 2026-09-09 bakeoff data (1,369 signal_emits in
  one day from one agent).
  - **Required input, not yet built (filed 2026-09-10 AM):** a McCoy
    cadence-by-hour breakdown — what the real call frequency is per hour
    and what actually drives it. 2026-09-09 night's relay flagged McCoy as
    possibly "stalled" after a 64-min quiet gap; the 2026-09-10 05:41 live
    check found 844 `decision_audit` rows in the prior 8h (calls at
    05:36-05:40, 1.75-3.39s, queue_wait 0.00) — not a fault, just
    after-hours quiet. The `_SCAN_TIER1/2/3` mechanism in `main.py` alone
    doesn't explain McCoy's actual observed cadence (far more frequent
    than its nominal 2-hour tier interval), and that gap in understanding
    is exactly the input 1.2's twice-daily redesign needs before its cut
    can be sized correctly.
- **signals_v2 rec #2 — scoped session, immediately after 1.2 lands.**
  Third known recurrence of this backlog problem — distinct root cause
  from the first two. HM-SIGNALS-V2-FIFO-STARVATION (2026-07-06) fixed
  strict-FIFO ordering (newest-first); HM-SIGNALS-V2-STARVATION-RECURRENCE
  (2026-08-29, after an 11,663-pending incident) reserved a small
  oldest-first slice per batch so the tail always makes progress. Neither
  addressed a sustained inflow-rate > throughput-rate imbalance, which is
  what's happening now: **pending is 4,023 as of tonight, not the
  2,894 last measured** — the backlog is actively growing, the exact
  failure mode rec #2 exists to catch. RULE #1 applies: stale rows are
  marked `expired`, never deleted — `signals_v2` keeps every row forever,
  same as `trades`.
  1. **Two sessions of post-1.2 backlog readings** (not before — Phase
     1.2's ~100x cut in scan volume changes the inflow side of this
     equation first) to separate inflow rate from throughput rate before
     designing the fix around a number that's about to move.
  2. **Age-ordered / priority lane in `engine/events_bus_consumer.py`.**
     Today's `consume_pending_signals()` (verified in code) does
     newest-first for the bulk of each batch plus a fixed reserve of the
     `_OLDEST_RESERVE = min(2, max_batch)` oldest rows — a fixed head-count
     reserve, not an age- or priority-aware lane. Replace with a real lane
     so freshness actually drives consumption order, not just a small
     constant carve-out.
  3. **Drain plan for the existing backlog** (2,894 at last count, 4,023
     now — use the live count when this session actually runs, not
     either historical figure): mark-expired by age and by dead source
     (a source with `halt_mode != 'active'` can never execute regardless
     of age — same category HM-SIGNALS-V2-FIFO-STARVATION already
     archived once), then drain what's left through the new lane. Marking
     `expired` is a status UPDATE, not a delete — no row ever leaves
     `signals_v2`.
  4. **Sentinel growth-rate check.** `scripts/hm_ops_sentinel.py::check_signals_v2_queue()`
     today (verified in code) only checks two static thresholds —
     `pending > QUEUE_PENDING_WARN` and `oldest_age_hours >
     QUEUE_OLDEST_WARN_HOURS` — no rate term at all. A backlog climbing
     steadily while the oldest-reserve mechanism keeps rotating enough old
     rows out to hold `oldest_age` under ceiling would pass both checks
     silently while `pending` keeps climbing. Add a growth-rate check
     (pending count vs. N cycles ago) that alerts at **T2** (per the
     Pushover redesign's tier scheme) even when age stays inside ceiling.
  **Acceptance:** pending count flat or falling over five sessions: no
  signal older than one session in the queue.
- **1.3 — ATR-scaled sizing in the gate, PLUS sizing/gate work re-scoped
  around McCoy's REAL gate chain (spec v2, 2026-09-11 — supersedes the
  2026-09-10 Gate-7-based draft below, still SPEC ONLY, not built).**

  **Why v2 exists:** the 2026-09-10 draft (kept below, struck through in
  spirit not in text, for history) targeted restoring `engine/
  crew_scanner.py` Gate 7 (`SNIPER_ALPHA_THRESHOLD`/`SNIPER_MIN_CONFIDENCE`).
  **A full trace on 2026-09-11 found Gate 7 governs a path
  (`_scan_single_agent()` via `SCAN_PAIRS`) that produced 272 decisions
  and 0 executed trades for McCoy in the 30 days before it went dormant
  2026-09-09 — not McCoy's real trading.** McCoy's actual trades flow
  through the Arena path (`ai_brain.py` -> `paper_trader.buy()`) and hit a
  completely different gate chain that Gate 7 never touches. Full trace:
  `data/reports/relay/relay_2026-09-11_mccoy_pipeline_trace_and_funnel.md`.
  This is the sixth premise this week that turned out wrong on inspection
  — the dry-dock halted for it, traced it, and this spec is the result.

  **ATR term (original scope, unchanged):** Today's stop/size math
  (`engine/stops.py`) is conviction-scaled but not volatility-scaled — two
  names at the same confidence get the same stop % regardless of how much
  they actually move. Adds an ATR term to the sizing gate so position size
  reflects the stock's own volatility, not just McCoy's confidence.

  **The real gate chain (`paper_trader.py::buy()`, confirmed by a 30-day
  funnel pull — 9,862 BUY signals -> 2 execution attempts -> 1 real
  trade):**
  1. `[HM-MARKET-CLOSED]` (before/after-hours/weekend) — 31.2% of all
     rejects. **Already fixed by Phase 1.2's cadence cut** (McCoy now
     only fires at 9:35 AM / 12:30 PM ET, both inside market hours) — this
     category should collapse to near-zero once 1.2 is live.
  2. `stale_signal` — 20.7% of rejects, the single largest remaining
     category. Not addressed by 1.2 or this spec; worth its own look
     before or alongside 1.3 if it's still large post-1.2.
  3. `engine.risk_manager.UNIVERSAL_MIN_CONVICTION` (currently **0.65**,
     `BEAR_MIN_CONVICTION=0.80` in bear regimes) — the REAL live
     confidence floor, not Gate 7's dormant 55. 11.4%+ of rejects
     (`LOW_CONVICTION: NN% below 65% minimum`, several buckets). **This is
     the correct target for the Sniper spec's `confidence >= 70%` intent**
     — raising `UNIVERSAL_MIN_CONVICTION` from 0.65 to 0.70 is the actual
     restoration, not touching Gate 7's constants.
  4. `engine.learning_engine.apply_learning()` — 11.1% of rejects
     ("Blocked by learning engine"). Real, live, currently applying a
     **flat `confidence_modifier=0.8` to every McCoy stated confidence**
     (frozen since 2026-07-08 — McCoy fell out of this pipeline's
     coverage 2026-07-09/13, see `docs/XO_BACKLOG.md`; root cause not yet
     found). Also enforces a regime filter, position-size cap, stop-loss
     override, a 3-losses-in-14-days ticker blacklist, and a cooldown —
     all still live for McCoy today. **See the coordination question
     below before touching this.**
  5. Regime router (`regime_mismatch` 9.4% + `REGIME-ROUTER: long_equity
     not approved in BEAR_CROSS` 5.4% = 14.8% combined) — already live,
     not part of this spec's changes.
  6. Bench rating (`BENCH: rating D (40/100)`, 3.0%) — already live, not
     part of this spec's changes.

  **Coordination question — resolve before building, not after
  (2026-09-11 finding):** `learning_engine.apply_learning()`'s
  `confidence_modifier` and `engine.calibration_map.
  get_calibrated_confidence()` are two independent confidence-adjustment
  mechanisms that do not know about each other. Wiring calibration_map in
  without addressing this double-adjusts McCoy's confidence uncoordinated
  (stated -> learning_engine's frozen x0.8 -> whatever calibration_map
  computes from a historical sample that had an *inconsistent*, time-
  varying multiplier baked into different parts of it). **Recommendation,
  for Admiral confirmation, not yet decided:** calibration_map should
  become the single source of truth for "how much to trust stated
  confidence" (used fail-open for the gate, fail-closed for sizing, per
  below); `learning_engine`'s `confidence_modifier` adjustment type should
  be retired once calibration_map has enough live data to replace it,
  with the other six `apply_learning()` adjustment types (regime filter,
  position size, stop-loss, ticker blacklist, ghost-promotion,
  cooldown) left untouched — those aren't confidence adjustments and
  don't conflict. Do not build 1.3's sizing against calibration_map until
  this sequencing is confirmed.

  **Alpha-scaled sizing tier (original April spec, restated) — wires into
  `paper_trader.py::buy()`'s existing, currently-unused-for-McCoy
  `sizing_multiplier: float = 1.0` kwarg** (confirmed 2026-09-11: the
  only live caller passing it explicitly today is `crew_scanner.py`'s
  `troi_caution_multiplier`; the Arena/McCoy path always calls `buy()`
  at the default 1.0). `composite_alpha >= 0.6` -> `sizing_multiplier=1.0`
  (full), `0.3–0.6` -> `sizing_multiplier=0.5` (half).

  **Confidence input to sizing — fails CLOSED on missing calibration data
  (unchanged principle from the 2026-09-10 draft):**
  `engine.calibration_map.get_calibrated_confidence()` deliberately fails
  OPEN (returns the raw stated confidence unchanged) when a regime/bucket
  has fewer than `MIN_BUCKET_N` observations — correct for a pass/fail
  gate, where "no evidence either way" shouldn't block a trade outright.
  It is **wrong for sizing**: letting unearned, uncalibrated confidence set
  position size in exactly the range with zero supporting data would let
  the sizing tier be driven by a number nobody has verified. Phase 1.3's
  sizing logic (not `get_calibrated_confidence()` itself, which stays
  fail-open) must apply its own rule on top: **when the relevant (regime,
  confidence-bucket) has no calibration evidence, size at the base
  allocation — never the 0.6+ full tier — regardless of how high the raw
  stated confidence is.**

  **Should the gate chain be loosened? No — measured, not assumed
  (2026-09-11).** Top 300 highest-confidence REJECTED McCoy BUYs, last 30
  days, forward return to next close (yfinance, close-to-close): mean
  +0.171%, **median -0.212%, win rate 45.8%** — at or slightly below a
  same-period SPY baseline (mean +0.034%, median -0.073%, win rate
  47.7%) on the two outlier-resistant metrics. Not the profile of a
  systematically profitable population being wrongly blocked. **This
  spec does not loosen any threshold** — `UNIVERSAL_MIN_CONVICTION`
  0.65->0.70 is a tightening, matching the original Sniper intent, and is
  supported by this measurement, not contradicted by it. Full detail:
  `data/reports/relay/relay_2026-09-11_forward_return_and_learning_engine.md`.

  **First real calibration read (2026-09-10, `scripts/print_calibration_curve.py`):**
  169 clean, non-placeholder McCoy trades stated confidence in 0.9–1.0
  (avg ~0.93); realized hit rate was **78.6%** — McCoy is roughly **15
  points overconfident** at the top of his stated range. Every bucket
  below 0.9 has zero coverage (no real observations survive after
  excluding the `confidence=0.0` data-placeholder contamination, see
  `docs/XO_BACKLOG.md`) — this is the first honest number this program has
  on what McCoy's stated confidence actually means, and it argues directly
  for the fail-closed sizing rule above: most of the confidence range has
  never been checked against reality at all.

## Phase 3 — BEAR_CROSS hedge routing

When regime = BEAR_CROSS, route to long the top-N (from Phase 2's ranking)
hedged with a SPY short or an inverse ETF, gate-sized. **No stock-level
shorts** — the hedge instrument is index-level only, keeping single-name
risk long-only per existing fleet convention (`config.py` short-selling is
already opt-in per agent via `is_short_enabled()` in `providers/base.py`;
this phase does not turn that on for McCoy).

## Phase 4 — Leakage & bias diagnostics

- **Ticker-masking leakage check:** re-run a Phase 2 arm with the ticker
  symbol redacted/replaced from the prompt (company description only) to
  test whether the score is actually reading the setup or just pattern-
  matching on which names it "likes." A large score delta between masked
  and unmasked runs on the same setup is a leakage signal.
- **Reverse-McCoy:** invert McCoy's own scored direction and track it as a
  **diagnostic only** — never a fleet seat, never executed. Purely answers
  "does McCoy carry information in either direction, or none at all" as a
  sanity check on the whole program.
